# 1. 获取周报

> 按《0. 接口文件模板》结构编写。
>
> **本文档是接口需求，不是既有接口的说明。** 尖括号处、以及「响应结构」和
> 「错误与异常说明」里标注「待确认」的部分，需要 OA 维护人按真实实现回填。

## 接口说明

| 项目 | 内容 |
|---|---|
| 功能 | 按周查询员工提交的周报正文，供周报整理工具汇总分析 |
| 请求方法 | GET |
| 完整接口地址 | `http://192.168.0.249/RibaoOA/api/OAWebApi/GetWeeklyReport` |
| Content-Type | 无（GET 请求，参数走 Query） |
| 鉴权方式 | 请求参数鉴权：userCode + password |

## 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|---|
| `userCode` | Query | string | 是 | OA 账号 | `dengcaiyue` |
| `password` | Query | string | 是 | OA 密码 | `******` |
| `week` | Query | string | 条件必填 | ISO 周编号 `yyyy-Www`。与 `startDate`/`endDate` 二选一 | `2026-W31` |
| `startDate` | Query | string | 条件必填 | 起始日期 `yyyy-MM-dd`，含当天。与 `week` 二选一 | `2026-07-27` |
| `endDate` | Query | string | 条件必填 | 截止日期 `yyyy-MM-dd`，含当天。与 `week` 二选一 | `2026-08-02` |
| `deptCode` | Query | string | 否 | 部门编码，按部门筛选。不填返回当前账号可见范围内全部 | `IT001` |
| `userCodes` | Query | string | 否 | 指定人员的 OA 账号，多个用英文逗号分隔。不填不限人员 | `zhangsan,lisi` |

## 请求规则

- `week` 与 `startDate`+`endDate` **至少提供一组**；两者同时提供时以 `week` 为准。
- `startDate` 与 `endDate` 必须成对出现，且 `startDate ≤ endDate`。
- 日期跨度上限 **31 天**，超出返回参数错误。周报整理工具单次只查一周，正常不会触碰该上限。
- `deptCode` 与 `userCodes` 同时提供时取交集。
- 返回内容受账号可见范围限制：接口只返回该 `userCode` 有权查看的人员的周报。
- 大数据量查询应缩小日期范围或增加筛选条件，避免影响 OA 服务。

## 请求示例

### GET 示例

```powershell
$uri = 'http://192.168.0.249/RibaoOA/api/OAWebApi/GetWeeklyReport?userCode=<OA账号>&password=<OA密码>&week=2026-W31'

Invoke-RestMethod -Method Get -Uri $uri
```

## 响应结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | number | 状态码，0 表示成功 |
| `message` | string | 结果描述，成功时为 `success` |
| `data` | array | 周报记录列表，无数据时为空数组 |
| `data[].userCode` | string | 提交人 OA 账号 |
| `data[].userName` | string | 提交人姓名 |
| `data[].deptName` | string | 所属部门名称 |
| `data[].weekNo` | string | 所属周，`yyyy-Www` |
| `data[].submitTime` | string | 提交时间，`yyyy-MM-dd HH:mm:ss` |
| `data[].content` | string | **周报正文全文**，保留原始换行 |

### 关于 `content`

这是本接口的核心字段，提三点要求：

1. **保留原始换行符**。周报整理工具靠换行和项目符号切分条目，正文被压成一行会导致整份周报只被识别成一条。
2. **返回纯文本**。若 OA 里存的是富文本/HTML，请在服务端转成纯文本再返回，不要返回 HTML 标签。
3. **不要截断**。不设长度上限，或上限不低于 8000 字符。

## 失败响应示例

```json
{
  "code": 1,
  "message": "OA账号或密码错误",
  "data": null
}
```

## 错误与异常说明

| 场景 | 表现 | 处理建议 |
|---|---|---|
| 参数缺失 | 待确认（预期 `code` 非 0，`message` 指明缺失参数名） | 检查必填参数和参数名 |
| 鉴权失败 | 待确认（预期 `code` 非 0，`message` 为账号或密码错误） | 检查 OA 账号、密码及接口权限 |
| 日期格式错误 | 待确认 | 按 `yyyy-MM-dd` 或 `yyyy-Www` 格式提交 |
| 日期跨度超限 | 待确认 | 缩小到 31 天以内 |
| 无匹配数据 | 待确认（**建议返回 `code: 0` + 空数组**，而非视为错误） | 调整查询条件或日期范围 |
| 服务异常 | 待确认 | 记录时间和错误信息后联系维护人员 |

> **「无匹配数据」希望按成功处理。** 那一周确实没人交周报是正常业务状态，
> 不是错误。若返回非 0，调用方需要额外分辨「真出错」还是「本来就没数据」。

## 注意事项

- 本接口为**只读查询**，不涉及任何写入。
- 调用方为内网周报整理工具，调用频率低：每周手动触发若干次，不存在轮询。
- 账号权限建议按最小可用授予：只需查看周报的权限，不需要其他 OA 功能。
